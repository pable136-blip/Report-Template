# 독립 작업공간 검증

- 기존 테이블과 자료를 유지하고, 새 세션·보고서 설정 테이블 및 nullable 소속 열을 추가.
- 부서명·보고서명 검색 후 숫자 4자리 비밀번호를 확인한 세션만 자료와 파일에 접근. 검색 목록에는 본문·파일·비밀번호 해시가 포함되지 않음.
- 세션 토큰은 HttpOnly/Secure/SameSite 쿠키로 보관하고, 서버에는 해시만 저장.
- 비밀번호는 보고서별 salt와 PBKDF2 해시로 저장. 원문은 저장하지 않음.
- URL 작업번호만 바꾸거나 다른 사업·파일 ID를 전달하여 다른 보고서를 읽거나 수정할 수 없음.
- 기존 자료 연결은 안내한 전용 비밀번호 확인 후 실행. 평문 비밀번호는 소스에 없음.

## 자동 검증
`node tests/workspace-isolation.cjs`는 SQLite에 실제 마이그레이션과 API SQL을 실행하고 파일 저장소만 메모리로 대체하여 다음을 검사합니다.

보고서 생성, 비밀번호 확인, 동일 브라우저의 다중 세션, 사업·설정·디자인 분리, 첨부파일 생성·조회·교체·삭제의 소속 확인, 이미지 참조 갱신, PDF 접근 분리, 세션 종료, 외부 Origin 거부, 기존 자료의 인증 후 연결.

`node tests/report-regression.cjs`는 편집용/출력용 화면 분리, 발표 화면의 변경 도구 제거, 긴 본문의 페이지 분할을 검사합니다.

실제 브라우저 클릭·PDF 렌더링·인쇄의 시각 검증은 별도 확인이 필요합니다.

4자리 PIN 형식(앞자리 0 포함), 공개 목록의 검색·비밀정보 제외, 기존 비밀번호 변경, 인증 없는 변경 거부, 반복 실패 잠금도 검증합니다.

비밀번호 없는 생성·열기, 비밀번호 설정/해제 후 다른 세션 만료, 보고서 이름 확인 없는 삭제 거부, 다른 보고서 세션으로 삭제 거부, 삭제 후 목록/기존 세션/직접 열기 차단, 기존 데이터 연결 보고서의 재생성 차단을 검증합니다.
